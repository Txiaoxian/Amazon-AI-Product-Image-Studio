# 用户模型授权、中文权限说明与登录验证码规格

## 状态

- 日期：2026-07-13
- 状态：已实现并完成 Docker、浏览器、自动化与安全验收
- 关联需求：权限说明中文化、用户级中转站/模型分配、登录页移除租户输入并增加验证码、管理员免验证码

## 目标

1. 权限目录以简体中文显示可理解的名称和说明，同时保留权限代码作为技术标识。
2. 管理员可以按用户分配可使用的中转站及其模型；普通用户只能看到并调用自己当前启用的授权模型。
3. 普通用户不具备中转站或模型的增删改查、授权管理入口，只能在生图参数中选择管理员分配的模型。
4. 登录页不再要求填写租户 ID；普通用户登录需要一次性图形验证码，管理员可以不填写验证码。
5. 用户级授权不仅影响页面列表，还必须在任务创建时由后端再次强制校验。

## 已确认的产品边界

本规格采用以下安全定义：

- 管理员维护用户的中转站和模型授权范围。
- 普通用户不能修改授权范围，也不显示中转站或模型管理页面。
- 普通用户不能新增、编辑、删除或测试中转站，不能新增、编辑、启用、禁用或删除模型。
- 普通用户不能修改中转站地址、API Key、并发限制、模型能力或价格配置。
- 一个模型天然归属于一个中转站，因此管理员按模型勾选即可同时确定“中转站 + 对应模型”的授权关系。

## 当前实现

- `permissions.name` 与 `permissions.description` 由后端以英文种子数据写入，现有权限管理页直接显示英文说明。
- `provider:read` / `model:read` 用户可以读取当前租户内全部中转站和模型。
- 任务创建只校验 Provider、模型、租户、启用状态和模型能力，不校验用户级模型授权。
- 登录请求中的 `tenantId` 已是可选字段；只有一个启用租户时后端会自动解析，多租户且未指定时会拒绝登录。
- 当前没有验证码接口或临时验证码存储。

## 方案概览

### 1. 中文权限目录

- 后端内置权限改为结构化目录：`code`、中文 `name`、中文 `description`。
- 启动时 reconciliation 更新既有内置权限的名称和说明，不改变权限 ID、代码或角色授权关系。
- 内置角色名称和说明同步中文化：管理员、普通用户、只读用户。
- 前端按权限代码提供中文兜底映射，避免数据库尚未完成 reconciliation 时继续显示英文说明。
- 权限代码仍以次级文本显示，便于技术排查和精确配置。

### 2. 用户级模型授权

新增租户级业务表 `user_model_access_grants`：

| 字段 | 说明 |
| --- | --- |
| `id` | 记录 ID |
| `tenant_id` | 租户隔离字段 |
| `user_id` | 被授权用户 |
| `model_id` | 被授权模型；中转站由模型当前的 `provider_id` 推导 |
| `granted_by` | 管理员授权人；系统迁移数据允许为空 |
| `created_at` / `updated_at` | 审计时间 |

约束：

- `(tenant_id, user_id, model_id)` 唯一。
- 用户、模型查询和写入必须同时过滤 `tenant_id`。
- 管理员、跨租户模型、已删除模型均不能通过普通用户授权接口越权访问。
- 现有用户在迁移时回填当前租户所有未删除模型，保持上线前“可见全部模型”的既有行为。
- 新用户默认没有模型授权，由管理员在用户管理页分配。
- 未来新建模型不会自动授予普通用户。
- 管理员不受用户级授权限制，但仍受租户边界约束。

运行时生效点：

| 外部可见状态 | 后端运行时消费者 | 本任务是否覆盖 |
| --- | --- | --- |
| 管理员分配的模型 ID | 模型列表与详情查询 | 是 |
| 管理员分配的模型 ID | 任务创建校验 | 是 |
| 模型启用/禁用状态 | 现有模型查询和任务校验 | 保持并回归验证 |
| 中转站启用/禁用状态 | 现有 Provider/任务校验 | 保持并回归验证 |

### 3. 登录验证码与租户解析

- 新增 Redis 临时验证码服务，验证码默认 2 分钟过期、一次性消费。
- 验证码图片由 Go 后端生成 PNG；前端不接收或持久化图片 base64。
- 登录失败统一返回不区分邮箱、密码、验证码哪一项错误的中文提示，降低账号与管理员身份枚举风险。
- 管理员角色由后端根据同租户用户角色判断，免验证码逻辑不能只做在前端。
- 登录失败限流继续生效；验证码 ID、答案、密码、Cookie 和 Authorization 不写日志。
- 登录请求继续兼容可选 `tenantId`，但登录页不再渲染该字段。
- 新增可选部署配置 `AUTH_DEFAULT_TENANT_ID`：请求未携带租户时优先使用该配置；未配置且只有一个启用租户时沿用自动解析；多租户且无默认值时返回统一登录失败，避免泄露租户状态，部署方应配置默认租户。

## API 契约

### `POST /api/v1/auth/captcha`

- 权限：无需登录。
- 请求体：无。
- 响应：

```json
{
  "data": {
    "captchaId": "opaque-id",
    "imageUrl": "/api/v1/auth/captcha/opaque-id/image",
    "expiresAt": "2026-07-13T12:02:00Z"
  },
  "requestId": "req_..."
}
```

- 错误：验证码临时存储不可用时失败关闭并返回脱敏 `500 INTERNAL_ERROR`。
- 安全：`Cache-Control: no-store`，不返回答案。

### `GET /api/v1/auth/captcha/{captchaId}/image`

- 权限：无需登录。
- 响应：`image/png` 二进制流。
- 错误：无效或过期返回 `404 NOT_FOUND`。
- 安全：禁止缓存，不返回验证码答案或 Redis 键。

### `POST /api/v1/auth/login`

- 请求体：

```json
{
  "email": "user@example.com",
  "password": "...",
  "captchaId": "opaque-id",
  "captchaCode": "AB34",
  "tenantId": "可选，保留兼容"
}
```

- 普通用户：`captchaId` 与 `captchaCode` 必填且一次性有效。
- 管理员：两字段可省略；若提供也不把验证码结果作为管理员登录前置条件。
- 响应：保持现有 `AuthSession` 不变。
- 错误：邮箱、密码或验证码不正确统一使用 `401 INVALID_CREDENTIALS` 和中文通用提示；限流保持 `429 RATE_LIMITED`。
- 前端影响：移除租户输入，增加验证码图片、输入框、刷新按钮、加载/失效/错误状态。

### `GET /api/v1/users/{userId}/ai-access`

- 权限：仅租户管理员。
- 响应：返回目标 `userId` 与已授权 `modelIds`；可分配模型目录由管理员现有模型列表接口加载并在前端按中转站分组。
- 跨租户用户 ID：`404 NOT_FOUND`。

### `PUT /api/v1/users/{userId}/ai-access`

- 权限：仅租户管理员，Cookie + CSRF。
- 请求体：

```json
{
  "modelIds": ["model-a", "model-b"]
}
```

- 语义：事务性替换管理员硬授权；空数组表示不授予任何模型。
- 请求中的模型成为该用户完整授权集合；未包含的既有授权会被撤销。
- 错误：非法、重复、跨租户或已删除模型返回 `422 VALIDATION_ERROR`；无权限返回 `403 FORBIDDEN`。
- 审计：记录用户 ID、授权模型数量和变更模型 ID，不记录 Provider 密钥或敏感配置。

## 前端交互

### 权限目录

- 每项首先显示中文权限名称。
- 第二行显示中文说明。
- 权限代码作为等宽次级标签显示，例如 `task:create`。
- 角色权限勾选区也显示“中文名 + 权限代码”，不再只显示代码。

### 管理员分配

- 在“用户/角色管理”的用户行增加“模型授权”操作。
- 弹窗按中转站分组，组内显示启用模型复选框。
- 明确显示中转站、模型名称、技术模型 ID、启用状态和当前授权状态。
- 保存时禁用重复提交，展示加载、空状态、权限错误和事务失败提示。

### 普通用户生图参数

- 普通用户管理菜单不显示中转站管理、模型管理或用户模型授权入口。
- 生图参数的模型下拉框只加载管理员已授权且当前启用的模型。
- 中转站名称作为模型选项的辅助信息显示，普通用户无需单独选择或管理中转站。
- 当前已选模型被管理员撤权或禁用后，刷新模型列表并自动选择剩余列表首项；没有可用模型时显示“请联系管理员分配模型”。

### 登录页

- 移除“租户 ID”。
- 验证码位于密码下方，含图片、输入框和“换一张”。
- 辅助说明：“普通用户需填写验证码；管理员可留空。”
- 任一登录失败后刷新验证码，旧验证码不得重复使用。

## 必须保持的现有行为

- JWT HttpOnly Cookie、CSRF、登录限流和 session version 机制不变。
- `tenantId` 登录请求字段保持可选兼容，不直接删除。
- Provider API Key 仍只在后端加密存储，前端只接收脱敏元数据。
- 管理员继续可以管理租户内全部 Provider 和模型。
- 任务状态仍使用 SSE，不增加轮询。
- 项目成员、资产与任务的现有对象级授权继续生效。

## 允许的中间态

- 中文权限目录可以先独立交付并通过测试。
- 数据表和 API 可以在前端入口隐藏时先落地，但普通用户列表过滤和任务创建强制校验必须在同一后端切片完成。
- 验证码后端可先通过接口测试验证，前端登录页切换后才算该切片完成。

## 禁止的半迁移状态

- 不能只过滤前端模型列表而不在任务创建时校验授权。
- 不能提供普通用户自助授权接口，也不能在普通用户界面显示授权管理或 Provider/模型管理入口。
- 不能让普通用户访问 Provider API，也不能让模型详情泄露未授权对象存在性。
- 不能仅在前端判断管理员免验证码。
- 不能把验证码答案、密码、API Key、Cookie、Authorization 或图片 base64 写入日志。
- 不能直接删除 `tenantId` API 字段，导致旧客户端无迁移期地破坏。
- 多租户且无默认租户时不能随意选择第一个租户。

## 失败模式与边界场景

| 场景 | 预期结果 |
| --- | --- |
| 普通用户无授权 | 模型列表为空，任务创建返回 403，页面提示联系管理员 |
| 普通用户使用未授权 modelId 直调任务接口 | 403，零任务、零事件、零入队、零成功审计 |
| 管理员跨租户分配模型 | 404/422，事务不写入 |
| 模型被禁用或软删除 | 授权记录可保留，但列表和任务运行均不可用 |
| Provider 被禁用 | 相关授权模型不可提交任务 |
| 管理员撤销正在使用的模型 | 已排队任务保持既有任务快照并继续由 Worker处理；新任务立即拒绝 |
| 验证码过期、错误或重复使用 | 普通用户登录失败，前端刷新验证码 |
| Redis 验证码服务不可用 | 普通用户失败关闭；不降级为无验证码登录 |
| 管理员不填验证码 | 正确账号密码可登录，仍受登录限流 |
| 管理员密码错误 | 返回与普通登录失败相同的通用错误，不暴露管理员身份 |
| 多租户且无 `tenantId` / 默认租户 | 不猜测租户，返回通用登录失败；部署方配置默认租户 |
| 只有一个启用租户 | 登录页无租户字段仍可正常登录 |
