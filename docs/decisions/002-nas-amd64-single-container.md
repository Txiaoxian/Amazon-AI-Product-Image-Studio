# ADR-002：为家用 X86 NAS 提供单容器部署包

## 状态

已接受

## 日期

2026-07-14

## 背景

目标设备是 16 GB 内存的 X86 极空间 NAS，构建主机是 Apple Silicon Mac mini M4。用户明确要求所有组件打包成一个 Docker，减少在 NAS 界面中配置多个服务的成本，同时要求重要数据落在外部硬盘并可重复构建部署。

仓库标准部署拓扑仍是前端、API、Worker、MySQL、Redis 和 MinIO 多容器。直接删除这些服务边界会影响现有部署和后续扩展，因此需要增加一个不改变应用接口的 NAS 专用打包层。

## 决策

- 新增 `deploy/nas-x86/` 专用拓扑，不修改标准多容器 Compose。
- 使用多阶段构建，把前端静态产物、Go API/Worker、MySQL、Redis、MinIO、Nginx 和 Supervisor 放入一个 `linux/amd64` 镜像。
- Nginx 是唯一公开入口；所有内部服务只监听 `127.0.0.1`。
- Supervisor 负责进程生命周期，容器健康检查同时验证六个内部服务和 Worker 就绪文件。
- `/data` 是唯一业务数据挂载根，包含 MySQL、Redis、MinIO 和 Provider 大图临时目录。
- Mac 构建脚本固定 buildx `linux/amd64`，直接输出可由极空间 Docker 界面导入的镜像归档和校验和。
- 镜像首次启动时生成独立随机密钥并保存到 `/data/config`，不在源码或镜像中保存真实凭据；因此只需映射 `/data` 和发布容器 `8080` 端口。

## 影响

- 符合单容器易部署目标，但任一底层服务升级都需要重建整张镜像，故障域也合并到一个容器。
- 容器需要以 root 入口初始化挂载目录和 MySQL，业务进程分别降权为 `mysql`、`redis`、`studio`；仅 Nginx 主进程和 Supervisor 保留容器内 root。
- 备份必须覆盖完整 `/data`，包括其中的 `config/` 密钥目录；最简单的一致性方案是停止容器后对数据目录做快照。
- 标准多容器拓扑继续作为公网、多人和可独立扩缩容场景的推荐方案。

## 被否决方案

### 只打包前端与 Go 服务，要求 NAS 另配数据库和对象存储

组件更轻，但不满足“全部打包成一个 Docker”和便捷部署要求。

### 在一个镜像内使用 SQLite 和本地文件替代 MySQL、Redis、MinIO

会改变平台数据、队列、SSE 和对象存储合同，形成难以维护的第二套应用实现，因此不采用。

### 在 M4 上构建本机默认 arm64 镜像

无法在 X86 NAS 原生运行。构建和部署两端都必须校验 `linux/amd64`。
