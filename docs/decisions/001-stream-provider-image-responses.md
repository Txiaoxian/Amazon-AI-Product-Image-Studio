# ADR-001：以临时文件承接大体积 Provider 图片响应

## 状态

已接受

## 日期

2026-07-14

## 背景

OpenAI 兼容中转站可能在 JSON 的 `b64_json` 字段中直接返回高质量图片。旧实现把完整响应读入内存，并对同一 JSON 做多次反序列化，再把 Base64 解码为新的字节切片。单张响应超过 128 MiB 时会被拒绝；接近上限时也会因 JSON、Base64 字符串和图片字节同时驻留而显著放大 worker 内存峰值。

用户不能控制中转站压缩方式，平台必须在不记录 Base64、不绕过资源保护的前提下可靠接收结果。

## 决策

- OpenAI 与 OpenAI 兼容成功响应使用流式 JSON 解码，`data` 数组按图片逐项处理，不再先读取完整响应。
- 每张 `b64_json` 解码到 worker 本地临时文件；Provider 返回 URL 时也以流式下载写入临时文件。
- 临时文件贯穿图片类型/尺寸校验、缩略图生成和 MinIO 上传，任务成功、失败、取消或重试退出时均删除。
- 用户上传限制与 Provider 生成图限制分离：前者继续由 `UPLOAD_*` 控制，后者由 `PROVIDER_MAX_OUTPUT_IMAGE_SIZE_MB` 控制。
- 保留有限但足够高的资源边界：默认 Provider JSON 响应上限 1024 MiB，单张解码图片上限 512 MiB；可用环境变量调整。
- API 调用日志只记录输出数量和脱敏 usage，不记录响应正文、Base64 或临时文件路径。

## 备选方案

### 只把 128 MiB 常量调大

实现简单，但完整 JSON、Base64 字符串及解码图片仍会同时占用内存，并发任务下可能触发 OOM，因此不采用。

### 要求中转站压缩图片或只返回 URL

无法保证所有兼容中转站支持，也把平台可靠性依赖于外部实现，因此不采用。

### 取消所有大小上限

会让异常或恶意响应耗尽磁盘、内存或租户存储配额，因此不采用。

## 影响

- worker 临时目录必须有足够可用空间，容量规划至少覆盖“并发生成任务数 × 单张输出上限 × 每任务输出数”。
- Base64 字符串仍由标准 JSON 解码器按单张图片短暂持有；相比旧实现，已消除完整响应、多次反序列化和解码后图片字节的长期并存。
- MinIO 与租户存储配额仍是最终持久化边界，临时文件不是业务数据源。
