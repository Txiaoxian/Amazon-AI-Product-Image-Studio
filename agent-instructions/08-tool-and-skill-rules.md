# 工具与 skill 使用规则

## 项目覆盖规则

本文件覆盖全局规则中对已删除或当前不可用专项 skill 的优先使用要求。

- 本项目不依赖全局 skill 使用规则中列举的专项 skill 清单，也不依赖其他未在当前会话中实际提供的 skill。
- 只有当前会话明确列为可用、与任务直接匹配且能带来实际价值的 skill 才能使用。
- 不得仅为满足全局“优先使用”偏好而暂停任务、搜索已删除的 skill、提示安装插件或向用户报告“专项 skill 当前未安装”。
- 专项 skill 不可用不构成阻塞，应直接使用仓库规则、项目文档、现有脚本、标准命令和当前可用工具完成任务。
- 用户明确点名某个不可用 skill 时，只需简要说明不可用，并在不改变需求范围的前提下使用常规流程继续；只有缺失能力确实导致任务无法完成时才请求用户处理。
- 不得因为 skill 可用而扩大用户授权范围，所有修改、验证和外部操作仍须遵循项目安全与交付规则。

## 默认替代流程

- 需求规划：阅读 `docs/`、相关代码和本项目规则，列出范围、约束与验收标准。
- Bug 修复：复现或检查证据，定位根因，增加回归测试，实施最小修复。
- 前端任务：遵循 `agent-instructions/03-frontend-rules.md` 和 `agent-instructions/06-testing-and-delivery.md`。
- 后端与接口任务：遵循 `agent-instructions/04-backend-rules.md`、相关契约文档和测试规则。
- 安全任务：遵循 `agent-instructions/05-security-rules.md`，并执行与风险匹配的检查。
- Docker、CI/CD 和 NAS 发布：优先使用 `deploy/` 中的现有脚本及部署文档，并执行产物架构、校验和、健康检查、重启和持久化验证。
- 浏览器验证：仅在任务确需真实页面交互且当前存在可用浏览器控制能力时使用；否则使用组件测试、接口测试、构建检查和明确的手动验证步骤。

## 沟通要求

- 无需向用户通报未被选用或不存在的 skill。
- 只有实际使用某个 skill、skill 明确要求暂停，或缺失能力确实影响交付时，才说明相关情况。
- 对用户的进度和交付说明应聚焦实际工作、验证结果和剩余风险，不罗列工具选择过程。
